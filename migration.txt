 Notes - BDD Logger (pour structurer les tests)

 Objectif
 - Utilitaire de test pour rendre les scénarios lisibles en console avec un style Given/When/Then.
 - Ne remplace pas SLF4J/Logback et ne pilote pas la verbosité des logs applicatifs.
 - Sert uniquement à tracer le déroulé d'un test (arrange/act/assert) d'une manière standardisée.

 Emplacement (référence dans l'API)
 - Classe: fr.avenirsesr.portfolio.common.testutils.BddLogger
 - Module: avenirs-portfolio-common (dans le repo avenirs-portfolio-api)
 - Fichier: libs/avenirs-portfolio-common/src/main/java/fr/avenirsesr/portfolio/common/testutils/BddLogger.java

 API (méthodes)
 - BddLogger.given(String message)
 - BddLogger.when(String message)
 - BddLogger.and(String message)
 - BddLogger.then(String message)

 Comportement
 - Chaque méthode écrit sur la sortie standard (System.out.println).
 - Préfixes affichés (exact): "GIVEN" / "WHEN" / "AND" / "THEN" (avec symboles).
 - Aucune dépendance Spring, aucune dépendance SLF4J: fonctionne dans tests unitaires purs et tests Spring Boot.

 Pattern d'utilisation observé dans l'API
 - Cas simple (test unitaire):
   - given("...")
   - when("...") + appel de la méthode
   - then("...") + assertions/verify

 - Cas service avec mocks:
   - given("a <Service>...")
   - préparation des mocks
   - when("calling ...")
   - then("it should ...")
   - verify(...) + assertions

 - Cas tests complexes: utilisation dans @Nested + @BeforeEach
   - given/and/when peuvent être posés dans des @BeforeEach de classes @Nested
   - then reste souvent dans la méthode @Test finale

 Exemples d'usage (copier/coller)
 - Exemple basique:
   - BddLogger.given("a service X")
   - BddLogger.when("calling doSomething")
   - var result = service.doSomething();
   - BddLogger.then("it should return ...")
   - assertEquals(...)

 - Exemple avec verify:
   - BddLogger.given("a mocked dependency")
   - when(dep.call()).thenReturn(...)
   - BddLogger.when("executing method")
   - service.execute();
   - BddLogger.then("it should call dependency")
   - verify(dep).call();

 Points d'attention / intégration
 - Pour l'utiliser dans un autre module (ex: security), il faut que la dépendance vers avenirs-portfolio-common
   soit disponible au moins en scope test (ou copier l'utilitaire si c'est la stratégie).
 - Ne pas confondre avec la configuration de logs (SLF4J/Logback). BddLogger n'empêchera pas l'affichage de log.error.
 - C'est volontairement simple: pas de configuration, pas d'assertions, uniquement du marquage de scénario.
